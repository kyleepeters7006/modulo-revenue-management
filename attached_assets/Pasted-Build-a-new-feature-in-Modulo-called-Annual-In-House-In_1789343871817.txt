Build a new feature in Modulo called Annual In-House Increase Plan.

The purpose is to take the completed/calculated annual in-house increase recommendation and turn it into a polished one-page executive decision document that can be:

* Viewed inside Modulo
* Expanded to full screen
* Printed
* Exported as a one-page PDF

This should answer four questions immediately:

1. What is Modulo recommending?
2. How much additional revenue will it generate?
3. How will the increase change the relationship between in-house and street rates?
4. Does the recommendation appropriately balance revenue growth with resident retention and market positioning?

Do not build this as a generic report. It should specifically summarize the output of the Annual In-House Increase calculation/planning tool already in Modulo.

⸻

ENTRY POINT

On the Annual In-House Increase calculation/results page, add a prominent button:

View Annual Increase Plan

This should use the currently calculated plan and open a polished report view.

Add these actions in the report:

Export PDF | Print | Full Screen | Back to Plan

Do not require the user to re-enter any information.

The report must use the exact same calculated plan currently displayed in the Annual In-House Increase tool.

⸻

Design this as an executive one-page document.

Use a landscape PDF if that produces the best layout.

Use Modulo’s existing:

* Rate formatting
* Branding

It should feel like a native part of Modulo, not a separate reporting application.

The page should tell this story visually:

Current Position → Recommended Increase → Revenue Impact → Future Rate Position

WHY MODULO RECOMMENDS THIS PLAN

Add a short section:

Why Modulo Recommends This Plan

Generate 2–4 concise sentences using actual plan data.

Do not produce generic AI commentary.

Explain the important economics.

For example, the logic might communicate:

“Current in-house rates are 6.4% below street rates. The recommended 5.8% average annual increase captures dependable revenue from the existing resident base while maintaining an estimated 2.1% discount to projected street rates immediately after the increase. Projected street-rate growth creates additional pricing room over the following 12 months.”

The actual text must dynamically reflect the calculated results.

Relevant factors can include:

⸻

CORE PRICING PHILOSOPHY

The report should reflect the pricing logic of the Annual In-House Increase model.

In-house increases are especially valuable because they apply to the existing resident base and therefore represent a relatively dependable source of revenue.

The model should attempt to capture appropriate annual in-house increases while also protecting against excessive increases that could create resident dissatisfaction or move-out risk.

Street-rate positioning is the key constraint.

Where possible:

In-House Rate < Street Rate

The objective is generally to bring in-house residents closer to street pricing without unnecessarily exceeding street pricing.

The report should make this balance visible.

⸻

PDF REQUIREMENTS

Export this entire report as a true one-page PDF.

The PDF should look like an executive presentation document.

Do not simply screenshot the browser page.

Charts must render sharply at PDF resolution.

Keep:

* Fonts readable
* Charts large enough to interpret
* Tables compact
* Margins professional
* No unnecessary navigation
* No browser UI
* No second page

If necessary, dynamically adjust chart heights or hide nonessential explanatory text to guarantee one-page output.

Do not remove the core recommendation, rate charts, variance comparisons or revenue impact to make it fit.

⸻

RESPONSIVE PLATFORM VIEW

The in-platform report should also work on desktop, tablet and mobile.

On desktop, show the complete executive report.

On mobile, allow sections to stack vertically for readability.

The PDF remains the one-page executive layout regardless of device used to generate it.

⸻

DATA INTEGRITY

This feature is a presentation layer for the Annual In-House Increase calculation.

It should NOT create a second calculation engine.

Create or use a shared structured data object representing the calculated plan.

The Annual Increase results screen, report preview and PDF should consume the same data.

Validate that:

1. Recommended increases reconcile to the detailed resident/unit plan.
2. Incremental revenue reconciles to the Annual In-House Increase calculation.
3. Weighted-average increases are calculated correctly.
4. Current-year impact accounts for the effective date.
5. Annualized impact represents the full-year run rate.
6. Street and in-house comparisons use matching time periods.
7. T3, T6 and T12 use the existing Modulo forecast assumptions.
8. SNF rates remain daily rates.
9. Senior Housing rates remain monthly rates.
10. NIC MAP benchmarks use the same data and methodology as Overview.
11. Every number shown in multiple locations on the report reconciles exactly.

⸻

FINAL DESIGN PRIORITY

Do not try to fill every inch of the PDF with information.

Prioritize visual hierarchy.

Within five seconds of opening the report, an executive should understand:

We are recommending X% → it generates $X → rates move from X% below street to X% below street → here is how that relationship develops over the next 12 months.

The existing Overview Street vs In-House charts should be the main visual evidence supporting that recommendation.
